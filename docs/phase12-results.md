## 主要测试证据

- 同一帧五指 DOWN；接触记录重排后槽位保持；原始 ID 可为较大且不连续的值。
- 抬起一个触点时同帧包含其他触点的 UPDATE；五指一起释放；刚按下即抬起先补 UPDATE，UP 保留最后成功位置。
- 可用槽位内同时 UP/UPDATE/DOWN；容量不足时先成功释放，再复用槽位；第二个提交失败时只清理此前成功保留的触点。
- 单指模式不跳到其他手指；置信度过滤；启动等待所有物理 Tip 抬起；超容量及重复 ID 取消。
- 注入 NOT_READY 时整帧相同地重试；耗尽重试不推进状态；参数错误按系统取消处理；清理失败保留状态并禁止新 DOWN；保活失败及遮挡错误取消。
- 2,000 次快速轻点模拟；1,000 个五指静止保活帧。
- 对容量 1..5 各生成 2,000 个触点变化帧，由独立 transport 状态模型检查完整活动集合、槽位占用、ID 稳定、UPDATE 前置条件及 UP 坐标，共 10,000 个输入帧（不包含额外产生的清理/拆分/保活提交）。
- 多指合成验收场景在纯逻辑 transport 上结束，所有生命周期配对，没有活动触点残留。
- 日志校验器覆盖系统 ID 与注入槽位不同、不同手指交错、UPDATE 合并、缺失接收、错误坐标、漏 UP、漏批次触点、日志丢失及损坏输入。

## 实现边界

有空闲槽位时同一输入帧的变化在一次 API 调用中提交。若旧触点释放与新触点加入的联合数组超出初始化容量，必须先提交释放帧，再提交新 DOWN；不能声称这两次调用是原子操作。

正常退出先请求工作线程清理，再让接收窗口继续处理约 300 ms 消息后关闭。这是实现与静态审查结果，仍需用真实窗口确认最后 UP 到达；没有以伪造接收事件代替测试。

当前最多 5 指，实际数量受设备与命令行容量限制；未读取硬件 Contact Count Maximum Feature Report。固定目标、原生鼠标冲突、500 ms 原始输入超时、Windows 特定参数行为、系统拒绝清理及强制退出等限制保留。真实两指缩放及第三方应用兼容性未证明。
