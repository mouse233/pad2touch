# Phase 0 技术可行性验证报告

测试日期：2026-11-16，Asia/Shanghai。

**结论：本机 Phase 0 验收通过。** 本机 Precision Touchpad 的原始多指坐标可经 Windows Raw Input 获取；真实触控板的单指移动已在固定矩形中转换成由 Windows 投递的 PT_TOUCH Down / Update / Up，并显示接收轨迹。尚未实现或验证多指同步注入。

## 环境

- 本机 Windows x64，内核 build `26300.9974`，注册表 DisplayVersion `26H2`。注册表 ProductName 为 `Windows 10 Pro`，该标签不足以独立确认产品营销版本；本次以实际 build 为准，没有测试另一套 Windows 10/11 系统。
- Rust/Cargo `1.98.1`，MSVC，Windows SDK `10.0.26100.0`，`windows-sys 0.61.2`。
- Raw Input 集合 1 个；`HID#ASUE1A03&Col02`，VID `04F3` / PID `32A0`，Usage `0D:05`。
- Report ID `4`，每条报告 `14` 字节，一个触点记录。多指以同一 Scan Time 的多条报告组成一帧。
- 描述符导出的 X 范围 `0..3987`、Y 范围 `0..2493`、Contact ID 范围 `0..15`。实际同时观察到五个触点；未读取 Contact Count Maximum Feature Report，因此不把描述符中 Contact Count 的逻辑上限 127 当成硬件最大指数量。
- 固定注入区域为桌面物理坐标 `[132,352)–[1028,728)`（右/下界不包含）。测试窗口临时置顶。
- 最终 Release 对照运行的进程令牌日志为 `token_elevated=0`，证明普通用户桌面环境可完成注入；工具解除执行限制不等于提升 Windows 管理员权限。

第一轮只能证明原始采集：当时验证程序的空闲逻辑反复解除注入准备状态，未产生注入。修正后第二轮完成端到端验证，不能把第一轮填报成注入成功。

对 `hardware-02` 和最终 Release 日志的独立分析结果：注入生命周期异常 0、接收生命周期异常 0、接收事件与成功注入事件的有序坐标匹配失败 0、结束时注入活动触点 false、接收活动触点 0。52 次按下均有对应释放。

注入帧数和接收消息数不完全相等：Windows 可合并 POINTERUPDATE，不能把这种差异直接解释为设备丢报或注入失败。所有收到的事件均匹配成功注入的类型和坐标序列。最终 Release 的 360 次注入对应 359 条接收事件，其中少一条 Update，Down/Up 均完整。

软件侧耗时：`hardware-02` 汇总的 InjectTouchInput API P95 为约 **0.147 ms**，从 Raw Input 回调开始到注入调用返回的 P95 约 **7.759 ms**。逐行日志重算 API P95 约 0.148 ms，1 µs 差异来自两次采样取时。最终 Release 合成对照 API P95 为 **0.351 ms**，合成步骤到注入返回 P95 为 **0.785 ms**。这些数字不含触控板扫描、固件、排队及最终接收延迟；不是物理端到端延迟或长期性能保证。最终版本仅对实际发生成功注入的输入帧收集输入至注入耗时样本，避免未准备期间的空操作影响统计。

## 构建与回归结果

- 仓库默认 `cargo test --offline --locked`：**8 项通过，2 项本机录制测试默认忽略**，克隆后不依赖本地输入数据。
- 在保留本地样本的测试机器上运行 `cargo test --offline --locked -- --include-ignored`：**10 / 10 通过**。Phase 0 原始验收也完整运行了这 10 项测试。
- `cargo clippy --offline --all-targets -- -D warnings`：通过。
- `cargo fmt -- --check`：通过。
- `cargo build --offline --release`：通过。
- 最终 Release 原生 API 实测：360 次成功注入，0 API 错误，31 对完整 Down/Up。

回归覆盖：描述符数据索引、Report ID 过滤、按钮缺省 false、坐标逻辑范围与有符号值、混合多报告组帧、并行填充、抬起记录、重复 ID/不完整帧/Scan Time 不一致、映射四角/中心/负原点/限幅、以及真实五指 HID 报告重放。

真实硬件端到端数据取自修正注入 ID 后的 Debug 实验构建；其后最终 Release 增加了更清晰的诊断文字、普通用户令牌记录及耗时采样筛选，并通过相同录制输入回归和独立原生注入实测。没有让用户再次重复整套硬件操作；不把最终 Release 合成测试说成再次完成了物理五指测试。

## 失败实验和已修正问题

1. 初期窗口被其他程序覆盖时，命中测试拒绝注入。后来把本次专用接收窗口临时置顶，并保留每点命中检查；不向遮挡窗口误投触摸。
2. 自动化受限执行环境中，初始化成功但注入出现错误 `6`。在普通交互桌面环境中继续参数对照；未更改系统设置，也未要求管理员启动。该错误的内部系统原因没有完全定位，不将其概括为所有受限环境都必然失败。
3. 初始化一个触点时使用注入 ID `1`，本机返回 `ERROR_INVALID_PARAMETER (87)`。单变量改为 ID `0` 后成功；最终实现固定使用 0。本机观察不能推导所有 Windows 版本的 ID 约束。
4. 空闲超过 500 ms 后曾无条件取消准备状态，导致抬手后下次操作不注入。修正为仅在确有活动注入时取消；第二轮真实硬件数据验证了间隔触摸、连续移动和抬起链路。

## 已知限制及未验证项

1. **多指采集已验证，多指同步注入尚未实现。** 本次只把一个稳定原始 Contact ID 映射为一个注入触点；额外手指不会生成多条触摸轨迹或捏合缩放。保留 Phase 2 范围。
2. **短时验证，不能声称长期稳定。** 五指同时活动只观察到 155 帧。未做数小时压力测试、端到端物理延迟测量、系统级丢报检测、CPU/内存基准或所有故障组合测试。0 解析错误不等于绝对没有底层报告丢失。
3. **本机设备和系统 build 限定。** 未验证其他厂商、外接 PTP、Windows 10/11 的其他 build、RDP、锁屏/安全桌面或高权限目标程序。
4. **原生鼠标及系统触控板手势继续工作。** 没有全局鼠标钩子、独占设备或修改设置/固件/Feature Report。多指手势可能同时触发系统窗口切换等操作。
5. **只映射固定测试矩形。** 未实现任意目标窗口、多显示器负坐标的实际注入、窗口动态移动/缩放、区域选择、旋转、校准或平滑。负坐标与边界仅经过纯函数测试。
6. **解析布局有边界。** 仅接收可由 HidP 字段分组解释的 PTP 报告；不支持的值数组/不同 LinkCollection 布局明确报错。Windows 预解析数据并非原始报告描述符，跨 Windows 版本重放不保证可用。
7. **错误恢复为实验级。** 实现了成功坐标 UP、NOT_READY 同帧有限重试、常规退出/设备移除/显示变化/窗口失效时取消、报告超时与保活。设备拔出、显示变化、API 故障等路径没有逐项真实触发验证；强制结束进程、崩溃、关机情况下不能保证本程序执行清理。没有 Phase 5 的重新连接和全面恢复。
8. **有限日志及耗时样本。** 队列满会记录丢失计数；耗时样本最多 100,000 个，显示轨迹最多 5,000 点。大规模长测需另行设计统计和日志策略。

Phase 0 验收在本机成立，可以据此评估下一阶段；本次没有继续开发后续功能。
